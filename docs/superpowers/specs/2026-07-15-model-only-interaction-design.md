# 仅人物区域交互设计

状态：已确认
日期：2026-07-15
分支：`feature/init`

## 1. 目标

桌宠窗口在常态下只允许 Live2D 人物渲染边界接收鼠标事件。人物之外的透明区域不响应点击、拖拽或右键，并将事件交给下层桌面或应用。

本设计覆盖此前“保留齿轮、聊天、麦克风和底部拖动条”的决定。

## 2. 常态界面

从 `DeskpetStage` 移除：

- 齿轮按钮。
- 聊天按钮。
- 麦克风按钮。
- 底部拖动短横条。
- 聊天气泡和聊天面板。
- 双击后出现的快捷输入框。

常态界面只渲染 Live2D 人物和必要的模型错误文字。模型错误文字不扩大窗口命中区域。

系统托盘菜单不属于透明 BrowserWindow，继续保留退出、重置和现有全局设置能力。

## 3. 鼠标交互

- 人物 bounds 内左键拖拽：移动整个 BrowserWindow。
- 人物 bounds 内右键：显示原生“设置 / 表情 / 动作”菜单。
- 人物 bounds 外：BrowserWindow 设置为鼠标穿透，不处理左键、右键、双击或拖拽。
- 拖拽开始后保持交互，直到 mouseup、失焦、按键状态丢失或组件卸载。
- 不恢复任何模型内部 offset 拖拽。

人物命中继续使用 Pixi `model.getBounds()` 转 CSS client bounds 的矩形判断，不改为逐像素透明度判断。

## 4. 设置例外

用户从人物右键菜单选择“设置”后，右侧设置面板临时成为人物之外唯一可交互区域：

- 只有实际 280px 设置面板矩形接收鼠标。
- 设置 overlay 的其余透明区域继续穿透。
- 关闭设置面板后立即恢复“只有人物可交互”。

表情和动作仍通过原生人物菜单调用现有 adapter/store 流程。

## 5. 旧状态迁移

旧版本允许拖动模型内部位置，可能在 localStorage 中留下把人物移出窗口的 `modelOffsetX/Y`。新版本不再提供内部拖动，因此模型加载时将遗留 offset 归零，只保留模型缩放和 BrowserWindow 位置。

这保证升级后人物不会因旧偏移不可见。

## 6. 代码边界

主要修改：

- `DeskpetStage.vue`：删除人物外 UI、相关状态和事件；只保留模型和设置例外。
- renderer 交互策略：以纯函数表达“拖拽中 / 人物命中 / 设置面板命中”的窗口交互决策。
- deskpet store 或加载流程：清除旧模型 offset。

不删除聊天、语音、设置等独立组件文件；它们可能被后续独立窗口或其他界面复用。本次只从桌宠透明窗口卸载。

## 7. 验证

自动化验证：

- 纯交互策略测试覆盖常态人物内外、拖拽中和设置面板例外。
- 旧 offset 迁移后为 `0,0`。
- 现有 bounds、拖拽、菜单和 IPC 测试继续通过。
- Node TypeScript 检查和生产构建通过。

Electron 实机验证：

1. 窗口内不再显示齿轮、聊天、麦克风和底部短横条。
2. 人物 bounds 内拖动可移动窗口。
3. 人物外透明区域点击和拖动不影响窗口，并作用于下层应用。
4. 人物右键仍显示设置、表情和动作。
5. 设置打开时仅右侧面板可交互，面板外仍穿透。
6. 重启应用后人物可见，遗留模型 offset 为零。
